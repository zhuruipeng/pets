## 一、先搞清楚一件事：你需要办几次备案？

App 备案和网站备案是**两件事**，但好消息是**可以复用**。

| | 网站 ICP 备案 | App 备案 |
|---|---|---|
| 备案对象 | 域名（`weiyuantool.com`） | App（`com.weiyuantool.pet_app`） |
| 提交入口 | 域名注册商 / 服务器厂商 | **服务器厂商或应用分发平台**（不是工信部官网） |
| 主管机关 | 山东省通信管理局 | 山东省通信管理局（按公司注册地） |
| 拿到的东西 | ICP 备案号（如 `鲁ICP备xxxxxxxx号`） | APP 备案号（如 `鲁ICP备xxxxxxxx号A1`） |

⚠️ **关键判断依据**：工信部明确规定
「**对于已履行网站备案手续的主办者，不需要重新填报主体身份信息，仅需补充 App 有关信息**」。

| 社交类 / 支付类 | ❌ | 无（隐私政策第五节已明写不接入） |
| 客服类 / 测试类 | ❌ | 无 |
| 安全风控类 | ❌ | 无 |
| 认证类 | ❌ | 手机验证码走**官网**，不是三方认证 SDK |

### 公钥怎么填（2026-10-04 实测踩坑）

⚠️ **输入框只接受「字母大小写 + 数字 + `+` `-` `=` `/` `,`」，不支持中文。**
**所以绝对不能填 Base64** —— Base64 含 `+` `/` `=` 与换行，会被拒（实测报红）。

**填「十六进制」格式**（我已从 `upload-keystore.jks` 的 `upload` 别名提取，512 字符 =2048 位 RSA 模数）：

```
C7338140AFD58D780DE8AD4CC36D77813C964906CBB52062A072CEB4917E276DBB4A6AE80A0C4C2A86DF8B57D5919E458D108853E0EABFD647CC836ED8DADF007BF852CBA740D8893232887046E8782E11578293CA667AB86B8FB09CD8A200F0103F3286313F3D9EFC16F25E957DE72B49A05BCBB940FC532E950B7298EDE1AE76E4F8EE2BD674563F0F8EF5F3E4109412907D5DF9D2F732C0D60A3EB76086AA24A8E77D711565381F31D98D12F76AB617F342D807E51859B21052E398DB662EB2ACF87222A922879AA273CE8D9B805116DFF232A3FF010FC850126545B7208D66D2E85F74A36963011D4B3F61D2A4876F2B38A5C395BAEB3B88181504EEA063
```

⚠️ **公钥是公钥，不是私钥。** 腾讯云要的是签名证书里的 RSA 公钥（用于校验签名），
这是公开信息，填进备案系统安全。**任何情况下都不能给私钥。**

**换签名后这三个数（公钥 / SHA-1 / MD5）全部会变**，备案信息也要跟着做变更。

自己重取的方法（换机器/换证书后）：

```bash
KS="app/android/app/upload-keystore.jks"      # 注意：不是 key.properties 里的相对路径基准
PROPS="app/android/key.properties"
ALIAS=$(grep '^keyAlias=' "$PROPS" | cut -d= -f2-)   # ⚠️ 字段名是 keyAlias，不是 storeAlias
PASS=$(grep '^storePassword=' "$PROPS" | cut -d= -f2-)
keytool -export -rfc -keystore "$KS" -alias "$ALIAS" -storepass "$PASS" -file cert.pem
openssl x509 -in cert.pem -noout -modulus | sed 's/^Modulus=//' | tr 'a-f' 'A-F'
```

⚠️ 顺带核一遍指纹，确认 keystore 找对了（应与 `apksigner` 从 APK 读出的一致）：

```bash
keytool -list -v -keystore "$KS" -alias "$ALIAS" -storepass "$PASS" | grep -iE "SHA1:|SHA256:"
```

### 负责人怎么填（⚠️ 山东是例外，主体/服务两个角色规则不同）

| 角色 | 山东要求 | 能不能填管理员 |
|---|---|---|
| **主体负责人** | **必须是法定代表人** | ❌ 不能 |
| **服务负责人** | 可以不是法人，**但必须上传「服务负责人授权书」** | ✅ 可以 |

**推荐：两个都填法人本人**，理由：

1. **免掉授权书**这一步 —— 少一道材料就少一个被驳回的理由；
2. 腾讯云支持「**使用负责人模板填充**」—— 服务负责人与主体负责人同一人时，
   只需做**一次**人脸视频核身，不用重复上传证件照；
3. 山东管局审核会**打电话核实**，填法人本人接通率最高
   （腾讯云：首次未接通 1 小时后再打，仍联系不上**直接驳回**）。

若确实要填管理员，需额外准备：
- [ ] **服务负责人授权书**（腾讯云后台「服务补充材料」处下模板，需**法人签字 + 盖公章**）

      四川/贵州/山东/青海/天津/上海/重庆），**不是可选材料**
- [ ] 管理员身份证正反面
- [ ] 管理员本人做**人脸视频核身**（微信扫码）
- [ ] 应急联系方式填管理员的（同样要能接通）

**应急联系方式**：按管局要求可能被强制填写，**必须能接通**，

## 七、能不能同时上苹果 App Store（中国区）？

**能，而且 iOS 比安卓省事得多。但 App 备案是两边共同的前置。**

### iOS 中国区 vs 国内安卓商店

| | 安卓（国内商店） | **iOS App Store 中国区** |
|---|---|---|
| 开发者账号 | 华为/小米/OPPO/vivo/应用宝**各注册一家** | **一个全球账号即可**，无需中国公司账号 |
| 软著 | 多数商店**必交** | **不强制**（安卓才必交） |
| 审核标准 | 各店不一，踩坑多 | Apple 统一标准，可预期 |
| 周期 | 6–12 个月（逐店过） | 提交后约 1–3 天 |
| ICP 备案号 | 必须 | **必须**（选中国大陆地区时强制填） |

### ⚠️ 关键：Apple 要的是「App 备案号」，不是网站备案号

App Store Connect 官方原文：「App 信息页面上的 ICP 编号和元数据应与
中国工业和信息化部的备案信息一致」，验证通过后会显示在产品页上。

- 现在手里的是**网站备案号** `鲁ICP备2026031884号-2`
- App 备案会拿到**独立新号**（形如 `鲁ICP备2026031884号-2A`，`A` 后缀）

👉 **正在办的这个 App 备案不只是安卓上架的前置，iOS 上架卡在同一件事上。
办了它，两边一起通。**

### 三个硬前提

1. **必须有 Mac**（硬卡点）。本机只有 Windows，没有 Xcode，iOS 包构建不出来。
   `app/ios/` 目录存在，但**从未在 Mac 上编译过** ——
   `flutter_secure_storage` 的 iOS Keychain 权限也从未在真机验证。
2. **苹果企业开发者账号**：688 元/年。需大陆营业执照 + 法人实名 + 对公信息。
   ⚠️ 个人账号（99 美元）不行—— **带注册登录的 App 必须企业账号**。
3. **iOS 版要单独构建**：i18n 双表已备好，但首次编译会有一轮调试
   （Keychain 权限、插件的 iOS 端配置）。

### 建议顺序

**先不动iOS。** 优先级：

1. **把 App 备案办下来**（正在做）→ iOS 与安卓的**共同前置**
2. 备案号到手后再考虑 Mac + 苹果账号
3. 有 Mac 后再做 iOS 首次构建

⚠️ 本App 无游戏/出版/宗教/新闻属性（宠物健康记录工具），
不需要 ISBN 出版物号或网络出版服务许可证。前置审批统一选「以上都不涉及」。
