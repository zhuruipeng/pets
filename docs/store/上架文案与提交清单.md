## 二、商店文案

### 中国区（应用宝 / 华为 / 小米 / OPPO / vivo）

**应用名称**：我的宠物

**副标题（≤ 30 字）**：疫苗驱虫提醒，一处记全

**一句话简介（≤ 60 字）**：
把疫苗、驱虫、体重、就医记在一处，到点自动提醒。数据只存在你手机里，照片不上传。

**完整简介**：

```
养宠之后，需要记住的事比想象的多：这针疫苗什么时候到期、上次驱虫是几号、
体重涨了没有、上次看病医生说了什么。

「我的宠物」把这些收在一处：

· 一页档案：品种、生日、体重、绝育、芯片号，加上它的小脾气
· 随手就记：体重、疫苗、驱虫、用药、就诊、喂食、排泄，支持补录
· 自动排期：按通用免疫规程生成疫苗与驱虫计划，到点提醒
· 照片留档：每个记录都能附照片，药盒、处方、化验单不再翻相册
· 走得明白：记遛狗轨迹与距离
· 家人共记：登录后邀请家人一起记录同一只宠物

关于隐私，我们做了两个明确的选择：
· 数据默认只存在你自己手机里，登录才同步
· 照片始终不上传服务器

没有广告，没有内购，没有埋点统计。
```

**关键词**：宠物,养宠,疫苗提醒,驱虫,宠物记录,狗狗,猫咪,宠物健康,遛狗,体重记录

**隐私政策链接**：✅ 已解决 —— 由宠物服务端自己托管（不依赖官网），
三个页面都在 `server/legal/`，随服务端一起发布：

| 页面 | URL |
| --- | --- |
| 隐私政策 | `https://api.pet.weiyuantool.com/legal/privacy` |
| 用户协议 | `https://api.pet.weiyuantool.com/legal/terms` |
| 注销账号 | `https://api.pet.weiyuantool.com/legal/account-deletion` |

（`/legal/privacy-policy`、`/legal/terms-of-use` 这类带后缀的写法也能打开，
省得商店后台输入框挑格式。）

**为什么放在服务端而不是官网**：这是宠物 App 自己的合规材料，跟着服务端
一起发布最直接（改文案与改接口在同一次发布里），也不必为了改一句话去动
另一个项目。将来想挂到 `weiyuantool.com/pet/` 下也可以 —— HTML 是自包含的
（样式内联、无外部依赖），复制过去即可。

⚠️ 上架前先自己打开这三个链接确认 200。文件没打进镜像时接口会返回 503
（不是 404）—— 那是「部署缺文件」，别当成「页面没做」。

**Full description**:

```
Vaccines, deworming, weight, vet visits — keep them in one place and get

· One profile: breed, birthday, weight, neutered, chip number, personality
```

## 四、签名（已完成）

发布包已配置正式签名：

- 密钥库：`app/android/app/upload-keystore.jks`（**已在 .gitignore 里，不会进仓库**）
- 配置：`app/android/key.properties`（同样不进仓库）
- 生效方式：`app/android/app/build.gradle.kts` 里「有 key.properties 就用正式签名，
  没有就退回 debug」

⚠️ **必须离线备份这两样东西**（U 盘 / 密码管理器）：

1. `upload-keystore.jks` 文件本身
2. `key.properties` 里的 `storePassword` / `keyPassword`

丢了就没有任何补救办法 —— 只能让所有已安装用户卸载重装，且商店会拒绝
用新签名覆盖旧签名的更新包。**这件事的重要性高于本文件里的其它所有待办。**

⚠️ 另外注意：**之前给你装的那个包是 debug 签名的，装不上这个正式签名的包**
（系统会拒绝签名不一致的安装）。换签名是一次性动作：先卸载旧版，装一次新版，
之后的应用内更新就都顺了。
