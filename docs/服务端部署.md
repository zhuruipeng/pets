# 服务端部署（中国区）

中国区服务端跑在 `caiwu-service`（腾讯云 124.223.174.129），对外域名
**`api.pet.weiyuantool.com`** —— 这个地址写在客户端 `app/lib/core/region.dart`
的 cn 分支里，**改它就得重新出包**，所以定下来之后不要轻易动。

> ⚠️ 这台机器上同时跑着官网 + ERP（`weiyuantool.com`）和 Ledgerly
> （`api.weiyuantool.com`）。它们正在服务真实业务，任何改动都要先确认
> 不波及它们 —— 下面「与邻居的边界」一节写了具体怎么做。

---

## 一、架构

```
App (cn flavor)
    │  HTTPS
    ▼
nginx  (api.pet.weiyuantool.com, 80/443)
    │        ├─ /download/*        → 静态文件 /var/www/pet-apk/
    │        ├─ /.well-known/...   → /var/www/acme（证书续期用）
    │        └─ 其余              → 127.0.0.1:8200
    ▼
gunicorn (2 × UvicornWorker)   ← systemd: pet-api.service
    │  ExecStartPre 建表
    ▼
PostgreSQL 15  (127.0.0.1:5432, 库 pet / 用户 pet)
```

| 项 | 值 |
| --- | --- |
| 代码 | `/opt/pet-api`（`app/` `legal/` `tests/` `deploy/`） |
| 虚拟环境 | `/opt/pet-api/venv`（Python 3.11） |
| 配置 | `/opt/pet-api/.env`（600，唯一配置来源） |
| 服务 | `pet-api.service`（绑定 `127.0.0.1:8200`，开机自启） |
| 数据库 | 独立库 `pet`，独立角色 `pet`，密码在 `/root/.pet-db-pass`（600） |
| 证书 | Let's Encrypt，`certbot-renew.timer` 自动续期 |
| 备份 | `pet-backup.timer` 每天 03:40，产物在 `/root/pet_backups` |

**只绑 127.0.0.1**：应用端口不对公网开放，入口只有 nginx 一个。

## 二、首次部署（脚本按序号跑）

`server/deploy/` 下的脚本都是**幂等**的，可以放心重复执行。

```bash
# 0) 把代码传上去（tar 打包，排除 __pycache__/.pytest_cache）
#    服务器上 /opt/pet-api 不存在时才解压，避免盖掉线上代码
tar czf /tmp/pet-server.tar.gz --exclude='__pycache__' --exclude='.pytest_cache' server/
scp /tmp/pet-server.tar.gz caiwu-service:/tmp/
ssh caiwu-service 'mkdir -p /opt/pet-api && tar xzf /tmp/pet-server.tar.gz -C /opt/pet-api --strip-components=1'

# 1) 建库建角色（密码只生成一次，重跑不会改）
bash /opt/pet-api/deploy/01-postgres-bootstrap.sh

# 2) venv + 依赖 + .env + systemd unit
bash /opt/pet-api/deploy/02-app-setup.sh
systemctl start pet-api

# 3) nginx 反向代理（**证书还没签时只会写 80 段，这是有意的**）
bash /opt/pet-api/deploy/03-nginx.sh

# 4) 备份
bash /opt/pet-api/deploy/04-backup-db.sh      # 先手工跑一次
bash /opt/pet-api/deploy/05-backup-setup.sh   # 再装定时器
```

**DNS 与证书**（一次性，需要 DNSPod 凭据）：

```bash
# 加 A 记录：api.pet -> 124.223.174.129
python server/deploy/dns-add-record.py --sub api.pet --value 124.223.174.129 --dry-run
python server/deploy/dns-add-record.py --sub api.pet --value 124.223.174.129

# 解析生效后签证书（webroot，不停 nginx）
/opt/certbot/bin/certbot certonly --webroot -w /var/www/acme \
  -d api.pet.weiyuantool.com --non-interactive --agree-tos --no-eff-email \
  --email zhuruipeng@weiyuantool.com --keep-until-expiring

# 证书就位后重跑第 3 步，443 段会自动补上
bash /opt/pet-api/deploy/03-nginx.sh
```

## 三、日常运维

### 改配置

```bash
vim /opt/pet-api/.env      # 唯一配置来源
systemctl restart pet-api
```

`02-app-setup.sh` **不会覆盖已存在的 .env** —— 重跑它不会把线上参数冲回模板值。

### 发新版（应用内更新）

两端版本号必须一致，改法见 `docs/自动更新-发布流程.md`。服务端这侧：

```bash
# .env 里改 APP_BUILD（必须等于 pubspec 的 +N），APP_NOTES 换成新说明
systemctl restart pet-api
curl -s https://api.pet.weiyuantool.com/app/version.json
```

新 APK 传到 `/var/www/pet-apk/`，文件名与 `APP_APK_URL` 一致。

### 看日志

```bash
journalctl -u pet-api -f                 # 应用日志（访问日志也在这）
tail -f /var/log/nginx/error.log         # nginx 侧
```

> gunicorn 会周期性打 `[INFO] Error while closing socket [Errno 9] Bad file
> descriptor`。这是 uvicorn worker 关闭连接时的已知噪音，**不是故障**。

### 更新代码

```bash
# 本地打包上传（同上），然后：
systemctl restart pet-api
```

重启会先跑 `ExecStartPre` 建表（有新增表时自动补），再起 worker。

## 四、备份与恢复

**备份**：`pet-backup.timer` 每天 03:40 跑一次，保留 14 天。
每次备份都会做两件校验 —— `pg_restore --list` 能读出归档目录（证明文件没坏），
以及归档里确实有表数据（证明不是空备份）。任一不通过都会记成服务失败。

**恢复演练**（每次升级 PostgreSQL、换服务器之后跑一次）：

```bash
bash /opt/pet-api/deploy/06-restore-rehearse.sh
```

它把最近一次备份恢复到一次性临时库，比对表/索引/约束数量与每张表的行数，
然后删掉临时库。**不碰生产库**。

**真出事要恢复**（会丢数据，务必先确认）：

```bash
systemctl stop pet-api
PGPASSWORD=$(cat /root/.pet-db-pass) pg_restore -h 127.0.0.1 -U pet \
  -d pet --clean --if-exists /root/pet_backups/pet-<时间戳>.dump
systemctl start pet-api
```

> ⚠️ `--clean` 会先删掉库里的现有对象。恢复前把当前状态也 dump 一份，
> 别把「恢复错了版本」变成两个版本都没了。

## 五、与邻居的边界

这台机器上三个项目共用一个 nginx。约定是**一个项目一个 `conf.d` 文件，
谁也不引用谁**：

| 文件 | 站点 |
| --- | --- |
| `caiwu-erp.conf` | `weiyuantool.com` / `www` —— 官网 + ERP（生产，最要紧） |
| `ledgerly-api.conf` | `api.weiyuantool.com` |
| `pet-api.conf` | `api.pet.weiyuantool.com` ← 本项目 |

因此有两条硬规矩：

1. **证书没有就绝不写 443 段。** nginx 启动时会去读 `ssl_certificate` 指向的
   文件，文件不存在就直接启动失败。而它此刻正给生产 ERP 挡流量 ——
   为上一个还没上线的 App 把在跑的生意打掉，代价完全不对等。
   `03-nginx.sh` 已经按这条写：证书在 → 写 80+443，证书不在 → 只写 80。

2. **改完必须 `nginx -t` 再 reload**，且失败要能回滚。脚本会在改之前备份原
   配置，`nginx -t` 不通过就还原并退出。

改完顺手确认一下别人的站点还在：

```bash
grep -rhE "^\s*server_name" /etc/nginx/conf.d/*.conf | sort -u
```

## 六、踩过的坑

### 多 worker 并发建表（首次部署必踩）

首启实测失败：systemd 显示 `activating (auto-restart)`，gunicorn 退出码 3，
日志里是

```
psycopg.errors.UniqueViolation: duplicate key value violates unique
constraint "pg_type_typname_nsp_index"
DETAIL: Key (typname, typnamespace)=(users, 2200) already exists.
```

两个 worker 同时跑 lifespan 里的 `create_all`，表还不存在，两边一起发
`CREATE TABLE`，一方必撞。靠 systemd 重启一次才起来 —— 也就是「第一次启动
一定失败」。**本地单进程 uvicorn 开发时永远看不到这个现象。**

修法是把建表提到服务启动之前，交给 systemd 的 `ExecStartPre`；表建好之后
`create_all` 走 checkfirst 直接跳过，不再产生 DDL。
`app/main.py` 里那份 `init_db()` 保留着给本地开发兜底，别删。

`deploy/verify-race.sh` 是这条的正反验证（跑在临时库上、跑完即删）：
A 组先建表再起双 worker → 200、0 冲突；B 组不建表直接起 → 服务起不来、2 次冲突。

### ACME challenge 的路径

nginx 写 `root /var/www/acme;` 时，URI 是**整段**追加的：

```
/.well-known/acme-challenge/xxx  →  /var/www/acme/.well-known/acme-challenge/xxx
```

手工放探针文件验证时，很容易放到 `/var/www/acme/` 下然后误判成「ACME 路径不通」。
certbot 用 `--webroot -w /var/www/acme` 会自己放对位置。

### 凭据类型别搞混

DNSPod 有两套凭据，**不能混用**：

| 凭据 | 调哪个 API | 长什么样 |
| --- | --- | --- |
| DNSPod Token | DNSPod API 2.0 | `ID,` + 32 位随机串 |
| 腾讯云 API 密钥 | DNSPod API 3.0（推荐） | `AKID...` 的 SecretId + 配对的 SecretKey |

拿腾讯云 SecretId 去调传统 API 会得到 `10003 传入的 Token 不存在` ——
错误信息不会告诉你「你拿错类型了」。判断依据：**DNSPod Token 的第二段
永远不带 `AKID` 前缀**。`deploy/dns-add-record.py` 会直接把这个判断打在脸上。

### 顺手修掉的仓库级问题

`core.autocrlf=true` 而仓库没有 `.gitattributes`，新写的 `.sh` 在 Windows 上
一旦被 checkout 就变 CRLF，传到 Linux 必然报
`bash: .../env bash^M: bad interpreter`。已加 `.gitattributes` 把 `*.sh`
钉成 LF。

## 七、还没做的

- **intl 区没有部署**：海外节点需要另一台机器（数据不出境是架构红线），
  且 intl 区要接邮件或国际短信通道。当前 `api.pet.example.com` 只是占位。
- **`/docs` 是公开的**：FastAPI 自带接口文档，任何人都能打开看接口结构。
  里面没有敏感信息（无密钥、无用户数据），但要不要关掉由你定。
  关的方式是在 `app/main.py` 建 app 时把 `docs_url=None`。
- **没有异地备份**：目前只有本机 `/root/pet_backups`，保留 14 天。
  机器整体故障时会连数据带备份一起没。ERP 那边有异地副本，可以照抄。
- **没有监控告警**：服务挂了不会有人知道（除非用户报障）。
