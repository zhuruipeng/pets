# 应用内自动更新：发布流程

这套东西解决的是「用户不用去应用商店，在 App 里点一下就更新完」。
链路很短，但**有三个环节任何一环断了都会静默失败**（用户只看到「已是最新」），
所以这份文档按「发一次新版要做哪几步」来写，而不是按代码结构写。

---

## 一、它怎么工作

```
App 启动 / 用户点「检查更新」
        ↓
GET  {区域后端}/app/version.json
        ↓
比对本机 build 号（Android versionCode）
        ↓
有新版 → 弹框（可强制）→ 下载 APK 到缓存 → 交给系统安装器
```

- 清单由**服务端环境变量**生成，不是静态文件 —— 中国区与海外区是两个独立部署，
  静态文件极容易只改了一边。改环境变量 + 重启服务即可发布。
- 界面上「设置 → 关于」里有「检查更新」入口；启动时也会静默查一次，
  失败或已最新**都不打扰用户**。

---

## 二、发一次新版，五步

### 第 1 步：抬版本号 + 出包（一条命令）

**别手改版本号。** 版本号同时出现在两个地方（`pubspec.yaml` 的 `+N` 与
服务端的 `APP_BUILD`），它们必须相等，而**没有任何东西会替你校验**。
漏了前者，用户收不到更新；漏了后者，用户收到提示、装完还是旧版 ——
后者更糟，因为它看起来像更新功能坏了，而这两种漏法都发生在
「构建成功、一切看起来正常」之后。

所以把它绑成一条命令（**在管理员终端里跑**：本机非提权进程执行 flutter 会撞
`CreateFile failed 231`）：

```powershell
# 中国区：抬 build → 出包 → 核对产物 → 打印服务端环境变量
.\app\tool\release.ps1 -Region cn -Notes "修复体重曲线在某些机型不显示"

# 海外区（AAB 上 Google Play）
.\app\tool\release.ps1 -Region intl -AppBundle -Notes "..."
```

它会做四件事：

1. 把 `pubspec.yaml` 的 build 号 **+1**（默认只动 build，不动版本名）；
2. 调 `build_apk.ps1` 出包（flavor 与 REGION 绑死，见下面的警告）；
3. **回读产物 `output-metadata.json` 里的 versionCode 与 pubspec 核对** ——
   不一致立刻失败，不让你带着错版本往下发；
4. 打印服务端要改的 5 个环境变量（可直接粘贴）。

只想看会变成什么版本、不想构建：

```powershell
.\app\tool\release.ps1 -Region cn -DryRun
```

上一轮构建失败了，想复用已经抬好的号（不再往上抬）：

```powershell
.\app\tool\release.ps1 -Region cn -NoBump
```

到了阶段节点想同时改版本名（如 0.1.x → 0.2.0）：

```powershell
.\app\tool\release.ps1 -Region cn -VersionName 0.2.0
```

> **为什么默认只抬 build、不动版本名**：客户端比对**只用 build**
> （Android versionCode），版本名只是给人看的。每次发版把 0.1.0 也一起 +1，
> 版本名会膨胀得很快（`0.1.37` 这种毫无信息量）。到阶段节点再用
> `-VersionName` 显式指定。

**原理（知道为什么，才知道什么时候它不管用）**：`+` 后面的数字就是客户端
拿来比大小的 `build`（Android `versionCode`）。比对规则是
「服务端 build > 本机 build 才算有新版」，所以**这个数字必须严格递增**。

同理，回滚一个坏版本时**不能把 build 改小** —— 那样比本机旧，客户端会认为
没新版。回滚要靠 `minBuild`：见第 4 步。

### 第 2 步：单出包（不发新版时才单独用）

`release.ps1` 内部就是调它，所以上一步已经出过包了。只有在
「不抬版本、只想打个包测试」时才需要单独跑：

```powershell
# 中国区
.\app\tool\build_apk.ps1 -Region cn

# 海外区（打包成 AAB 上 Google Play）
.\app\tool\build_apk.ps1 -Region intl -AppBundle
```

产物：`app/build/app/outputs/flutter-apk/app-release.apk`（或
`app/build/app/outputs/bundle/<region>Release/`）。

> ⚠️ **别手敲 `flutter build apk`**。flavor 和 `--dart-define=REGION`
> 是两个互不校验的参数，漏掉后者会打出一个「Android 侧是中文区包、
> Dart 侧按海外区跑」的错包：接口指向海外节点、地图开关也错。
> 这种包能装能启动，只有联网才露馅。脚本把两个值绑死了。

> 想分架构减小体积，加 `-SplitPerAbi`。但那样会出三个 APK，而清单里
> 只能填一个 URL，所以**发自动更新时用全架构包**。

### 第 3 步：把 APK 传到一个 HTTPS 直链

对象存储 / CDN 都行，不必与接口同域。两条硬要求：

- **必须 HTTPS**。Android 9+ 默认禁止明文 HTTP，用 `http://` 下载会直接失败。
- **直链要稳定**。别用带时效签名的 URL，那份 URL 会被写死在清单里。

### 第 4 步：改服务端环境变量并重启

两区**各自**设置（`.env` 或部署平台的环境变量）：

```bash
APP_VERSION=0.2.0
APP_BUILD=2                        # 必须与 pubspec 的 +2 一致
APP_APK_URL=https://cdn.example.com/pet-app-0.2.0.apk
APP_NOTES=新增照片附件；修复体重曲线在某些机型不显示
APP_MIN_BUILD=0                    # 填 2 表示 build<2 的用户被强制更新
APP_IOS_STORE_URL=                 # 中国区留空；海外区填 App Store 链接
```

`APP_NOTES` 里换行即分段，会自动显示在更新弹框里。

**关于 `APP_MIN_BUILD`（强制更新）**：这是唯一能把用户从坏版本上拉回来的手段。
只有真的出了严重问题才动它 —— 强制更新没有「稍后」，用户只能装完才能用 App。

### 第 5 步：验一遍

```bash
curl -s https://api.pet.weiyuantool.com/app/version.json
```

期望看到 `build` 与刚发的包一致。然后拿**旧版**的手机点「检查更新」，应当弹框。

## 三、签名：这条不弄好，更新一定失败

系统拒绝安装「签名与已装版本不一致」的包，报错只有干巴巴一句**「应用未安装」**，
没有任何提示指向签名。所以：

- `app/android/app/build.gradle.kts` 里已支持正式签名：
  在 `app/android/key.properties` 放四项（**该文件不进版本库**）：

  ```properties
  storePassword=***
  keyPassword=***
  keyAlias=upload
  storeFile=/absolute/path/to/upload-keystore.jks
  ```

- **有 `key.properties` 就用正式签名，没有就退回 debug 签名**（本地能跑，能出包）。
- ⚠️ **当前仓库还没有配正式签名**，也就是现在的包用的是 debug 签名。
  后果：只有**同一台机器**（`~/.android/debug.keystore` 不变）出的包能互装；
  换机器、重装系统后，老用户必须卸载重装。

  一旦开始给真实用户分发，**第一件事就是生成 upload keystore 并备份**：

  ```bash
  keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA \
    -keysize 2048 -validity 10000 -alias upload
  ```

  keystore 和密码丢了 = 所有用户卸载重装，没有别的补救办法。

## 四、踩坑清单

| 现象 | 原因 |
| --- | --- |
| 点「检查更新」一直「已是最新」 | build 号没抬；或服务端 `APP_BUILD` 没改；或两区只改了一边 |
| 弹框出来了，下载失败 | APK 直链是 `http://`（Android 9+ 禁明文）；或缺 `INTERNET` 权限 |
| 下载完跳到安装器，装不上 | 签名不一致 —— 见上一节 |
| 点了「立即更新」没反应，只提示去设置 | 用户没授权「安装未知应用」。Android 8+ 是按应用单独授权的，代码会引导去设置页 |
| 强制更新弹框关不掉 | 这是设计如此（`minBuild` 生效），只有装完新版才能继续用 |
| iOS 上点检查更新提示不支持 | 正常。Apple 不允许 App 自己下载安装包，只能跳商店 |

---

## 五、为什么不做「热更新」

Flutter 官方不支持热更新；第三方方案（Shorebird 之类）会改动整条构建链，
iOS 上还直接违反商店规则（审核指南 3.3.2）。本项目的更新频率用「自更新 APK」
完全够用。**真要改行为而不想发版，走远程配置**（如免疫规则集）那条路，
而不是换代码。
