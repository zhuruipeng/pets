# 安卓与苹果共用代码

同一份 Flutter 项目分别构建 Android 和 iOS。宠物档案、家庭照护看板、用药疗程、删除宠物、数据库与同步继续共用；苹果新增功能通过平台能力配置和原生桥接接入。

## 平台与地区分开管理

| 构建 | 应用标识 | 地区配置 |
|---|---|---|
| Android cn | `com.weiyuantool.pet_app`，保留已安装用户的原标识 | `dart_define/cn.json` |
| Android intl | `com.weiyuantool.pet` | `dart_define/intl.json` |
| iOS cn | `com.weiyuantool.pet.cn`，申请商店记录前确认可注册 | `dart_define/cn.json` |
| iOS intl | `com.weiyuantool.pet`，保留现有标识 | `dart_define/intl.json` |

两区分别使用原有区域后端与数据库；选择 iOS 不会改变地区、账号体系或数据节点。iOS cn / intl 可安装为两个不同应用，各自保存数据。

- `app/lib/core/region.dart`：区域后端、单位、语言等地区规则。
- `app/lib/core/app_capabilities.dart`：共享功能与平台能力的唯一查询入口。
- `app/lib/core/feature_flags.dart`：尚未完成的功能开关，需写明开放条件。
- `app/android/`、`app/ios/`：各平台权限、签名与原生扩展。

| 功能 | Android | iOS |
|---|---|---|
| 宠物档案 / 家庭照护 / 用药疗程 / 删除宠物 | 共用 | 共用 |
| APK 下载与安装更新 | 开启 | 关闭，避免安卓强制更新影响苹果 |
| GPS 遛狗轨迹 | 暂未开启 | 暂未开启 |
| 苹果小组件 / 快捷指令 | 关闭 | 已预留配置，原生功能尚未开发 |

将来添加苹果功能：在 `AppFeature` 定义能力 → 写原生实现与 Dart 桥接 → UI 查询 `AppCapabilities.current.supports(...)` → 验证后开启对应开关。不要在不同页面散落 `Platform.isIOS` 判断。数据库迁移与同步不能因 UI 开关跳过已有数据。

iOS 上架后，如需应用内更新提示，应单独接 App Store 信息，使用 iOS 的版本与商店地址，不能复用 Android 的 `build / minBuild`。

## 现在在 Mac 上做什么

开发者账号未获批时，先用 iOS 模拟器开发和验证。模拟器不需要分发签名。个人 Apple Account 可用于 Xcode 的个人团队真机调试，但能力与签名有效期有限；TestFlight / App Store 分发等开发者计划获批后配置。

1. 安装完整版 Xcode，启动一次完成组件安装，在 Xcode 设置中安装所需的 iOS Simulator。执行 `xcode-select -p` 确认使用 Xcode，而不是单独的 Command Line Tools。
2. 安装 Flutter 与 CocoaPods，加入终端 PATH。建议与这次验证的 Flutter `3.47.4` / Dart `3.13.3` 保持一致；不要删除 `pubspec.lock`。
3. 在 Mac 仓库中拉最新代码后执行：

```bash
git pull --ff-only
cd app
flutter doctor -v
flutter pub get
python3 tool/check_platform_config.py
python3 tool/apply_ios_release.py --check
flutter analyze
flutter test
open -a Simulator
```

如 CocoaPods 装在 Ruby 用户目录中，把其 `bin` 目录加入 PATH，确保 `pod --version` 成功。项目在 `pubspec.yaml` 内关闭 Swift Package Manager，保持现有 CocoaPods 集成，不依赖 Mac 的全局 Flutter 设置。构建脚本不会删除代理环境变量；需要联网下载依赖时使用 Mac 上可用的网络配置。

用模拟器运行其中一个市场：

```bash
flutter run --flavor cn --dart-define-from-file=dart_define/cn.json
flutter run --flavor intl --dart-define-from-file=dart_define/intl.json
```

存在多台设备时用 `flutter devices` 查看，并给 `flutter run` 加 `-d <设备ID>`。进入「我的」debug 诊断，确认地区与 API 节点匹配。验证添加宠物、家庭照护、疗程记录与删除宠物；通知、相机、Keychain 登录及多设备同步仍需真机验证。

## 统一构建入口

命令从 `app/` 目录执行；脚本自身也会切换到项目目录。`--region` 必填，自动绑定同名 flavor 与 Dart 地区文件。默认不修改版本，不上传安装包，不发布应用。

```bash
# Mac：不需要开发者分发账号的模拟器构建
python3 tool/build_mobile.py --platform ios --region cn
python3 tool/build_mobile.py --platform ios --region intl

# Mac：编译设备版，但不签名。产物是 Runner.app，不可直接安装或上架。
python3 tool/build_mobile.py --platform ios --region intl --format unsigned

# Android APK / Google Play AAB
python3 tool/build_mobile.py --platform android --region cn --format apk
python3 tool/build_mobile.py --platform android --region intl --format aab

# 任意电脑：只验证配置和展示命令，不编译
python3 tool/build_mobile.py --platform ios --region cn --dry-run
```

可用 `--flutter /完整路径/flutter` 指定 SDK。Windows 现有 `tool/build_apk.ps1` 与 `tool/release.ps1` 的流程保留，正式 Android 更新继续使用原 keystore，防止老用户无法覆盖安装。

iOS 构建产物位于 `build/ios/iphonesimulator/Runner.app` 或 `build/ios/iphoneos/Runner.app`。两区共用构建目录，后一轮会覆盖前一轮产物；需要保留两份时分别复制保存。

旧 Mac 脚本 `zsh tool/build_ipa_intl.sh` 仍可生成海外未签名 IPA，已改用 intl scheme。未签名 IPA 也不代表可直接安装、TestFlight 测试或 App Store 上传。

## 开发者账号获批后

1. 在 Apple Developer 注册需要发布的 Bundle ID，在 App Store Connect 建立对应应用。应用标识一旦发布不要随意变更。
2. 打开 `app/ios/Runner.xcworkspace`，给 Runner 的相应构建配置选择你的开发团队及签名。团队 ID、证书、描述文件、API 密钥不提交到 Git。
3. 先验证真机流程，再构建签名包：

```bash
cd app
python3 tool/build_mobile.py --platform ios --region intl --format ipa
# 如需发布中国区，改为 --region cn。
```

4. 核对地区、桌面名称、版本、权限文案和隐私材料，再通过 Xcode / Transporter 上传并测试。本轮尚未配置你的团队签名，也未上传应用商店。

从 Xcode 运行时选择共享的 `cn` 或 `intl` scheme。各自的 Debug / Profile / Release 配置包含对应 Pods 和 Flutter 配置，并补入所选市场的 REGION，避免上次生成的配置残留。Flutter 构建阶段会校验 native market 与有效 Dart REGION；有效地区错配时会停止构建。

不要用 `flutter create` 覆盖整个 `ios/` 目录，否则可能丢失 scheme、权限、图标和隐私资源。Windows 的静态校验只能检查配置结构，最终需要在 Mac 上分别编译两区。

参考：[Flutter iOS flavors](https://docs.flutter.dev/deployment/flavors-ios)、[Apple 开发者账号与个人团队](https://developer.apple.com/help/account/basics/about-your-developer-account)。
