# 症状观察、临时照护交接与本地备份

本轮功能共用 Flutter 代码，同时适用于 Android / iOS 和中国区 / 海外区。没有增加登录门槛，也没有开启尚未实现的苹果小组件或快捷指令。

## 症状观察

入口：档案 → 健康 → 症状观察，或者「记一笔」→ 症状观察。

- 记录呕吐、软便、咳嗽、瘙痒、食欲变化、精神变化及其他情况。
- 次数可不填；填写时限 1–1000 的整数。食欲、精神、排便状态分别保存。
- 可回填发生时间、备注，并关联同一只宠物的就诊记录或用药疗程。
- 保存后在记录详情添加照片、检查文档；观察同样进入时间线、健康报告和现有手动同步流程。
- 观察页展示最近七天的记录条数与各观察项目的条数，统计的是观察记录，不是累计发生次数。
- 主人和编辑成员可以新增，查看成员只能阅读。已删除或其他宠物的就诊 / 疗程不能作为新关联。

数据使用 `records.type = symptom` 和稳定的 payload code，无需提升现有 schema v7。界面显示时才翻译；此功能记录主人所见，不生成诊断。

## 临时照护交接卡

入口：档案 → 健康 → 临时照护交接卡。

选择交接日期，填写饮食、散步及其他照护说明，预览后通过系统分享保存或发送 PNG 图片。

卡片包含宠物名称、交接日期、过敏信息、最近一次喂食内容、期间有效且启用的用药疗程，以及交接结束前的待办提醒（包括尚未处理的逾期提醒）。疗程显示剂量、给药方式、每日时间及原定起止日期。

联系人开关控制是否加入当前用户已填写的姓名 / 电话 / 邮箱 / 微信 / 补充说明。预览图可供分享前检查。历史费用、芯片编号和完整就诊台账不会自动放入交接卡；图片生成后不会随应用内变化自动更新，交接前需核对实际用药安排。

复用现有长图绘制器，支持长说明及中文，并为 iPad 分享提供弹出位置。

## 本地备份与恢复

入口：我的 → 备份与恢复。

导出 ZIP 后，需要在系统分享窗口完成保存。建议存到用户自己的文件目录或云盘。

备份范围是本机数据库中的宠物档案（含归档 / 软删除数据）、记录、提醒、费用、完成日志、遛狗历史、标签、附件元数据，以及实际存在的本机宠物头像、照片和文档。可选恢复昵称与联系方式。仅存在于其他设备或服务端、尚未同步到本机的内容不在备份中；远程附件保留链接，未缓存文件不当作本机文件打包。

恢复前会展示备份时间和宠物 / 记录 / 文件数量，确认后按新副本导入：

1. 为所有对象生成新 ID，并迁移就诊、疗程、给药记录、费用和完成日志间的关联。
2. 附件落到新手机的应用文件目录，不保留旧手机绝对路径。
3. 保留当前已有资料；同一份快照重复恢复会被拒绝。
4. 恢复的提醒全部暂停，主人检查后再逐一启用。归档和软删除状态保持原样。
5. 新副本归属于当前本机用户。登录身份、邮箱身份、共养成员授权、登录 token、同步游标和旧发送队列不恢复；共享关系需要重新配置。
   原照护者姓名作为备份历史保留，完成日志不将导入者标记为原执行者；给药记录保留原姓名元数据，以免后续同步覆盖历史展示。已删除宠物的副本留在本机，不生成无法获得服务端主人权限的上传队列。
6. 对 ZIP 条目和大小预检，再核对文件大小及 SHA-256。拒绝损坏文件、路径穿越、重复条目、符号链接、未知格式版本及地区不匹配。数据库写入使用单个事务，失败时回滚并清理本轮文件。

格式标识为 `mypet-local-backup`、版本 1、schema 7。仅支持相同地区和当前 schema；压缩文件及展开总大小各限 512 MiB，manifest 限 16 MiB，媒体条目最多 20,000。导出缺失且没有远程链接的本机附件时会中止，避免产生不完整备份。

ZIP 没有加密，里面可能含联系人和健康资料，应保存在自己的存储位置。自动云备份、覆盖式还原和跨地区迁移尚未实现。

## 发布验证

自动化覆盖观察权限与关联、照护日期 / 范围、中文英文小屏页面、PNG 实际绘制、跨设备附件迁移、损坏包拦截、重复恢复、事务回滚及同步权限。

Windows 无法验证 Xcode 编译和 iOS 系统分享 / 文件选择的真机行为。发布前需在 Mac / iPhone 实测：备份保存到「文件」→ 另一设备恢复 → 打开照片 / PDF → 检查暂停疗程 → 分享交接卡；Android 同样需执行此流程。本轮不抬版本号、不发布安装包、不变更线上更新清单。
