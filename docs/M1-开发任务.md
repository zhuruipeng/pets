### 评审收口改了什么

| 改动                         | 理由                                                     |
| -------------------------- | ------------------------------------------------------ |
| 底部栏 5 Tab → 4 Tab，删日历页与发现页 | 日历本可由首页 Upcoming 承担；发现页是个「什么都有」的杂物箱，拉低主线清晰度            |
| 首页去掉健康评分与活跃度               | 两项都是伪指标：「状态：良好」是自己给自己打分，「活跃度」恒为 `--` 永远填不上。首页只陈述查得到的事实 |
| 硬砍 AirTag/BLE 防丢标签与走失协查    | 前者是与第三方标签的生态绑定，后者涉 UGC 与隐私合规。V1 不碰，连灰入口也删              |

| 「免疫计划」→「建议排期」              | 原名暗示确定性，与「建议性内容」的合规口径冲突                                |
| 建档改问卷式                     | 单页长表单的中途放弃率高于分步问答；问卷只问三个能改变输出的问题                       |
| 档案页 5 页签 → 4 页签            | 砍「文件」页签（与记录页职能重叠），其余合并为「记录」                            |
| 保留「回忆」页签                   | 上一版把它做成「照片按时间聚合」的空态是错的 —— 它应是长期留存的情感锚点，值得单列            |

## 本轮实现中修掉的真实问题

1. **`PlanItemType` 与 `String` 比较** —— 生成计划时拿枚举去比字符串集合，去重逻辑实际失效，会重复建提醒。已改为 `.wireName`。
2. **自检面板值重名** —— 区域名和免疫规则集都是 `intl`，界面上看起来像重复行。已加 `region:` / `rules:` 前缀。
3. **测试进程残留占用 `sqlite3.dll`** —— 导致 `flutter test` 报「无法删除文件」而整体失败。解法：结束残留 `flutter_tester` 进程后重跑。
4. **体重字段名写错** —— 新版首页主卡曾按 `PetRecord.weightKg` 取值，实际体重存在 `valueNum`（公制 kg），会导致整页编译不过。已改回 `valueNum`，并在 `Units` 补了只出数字的 `weightNumber`。
5. **`TodoTile` 漏建** —— 首页待办小卡引用了 `widgets.dart` 里并不存在的 `TodoTile`。已补齐。
6. **`const` 里夹运行时调用** —— `const _PageTitle(L.t('me.title'))` 编译不过，已去掉 `const`。
7. **待办操作条标题重复** —— 副标题把提醒标题又拼了一遍，已改为只显示倒计时。
8. **条件性 `ref.watch`** —— 发现页在两处把 `ref.watch` 塞进三元 / `if`，条件翻转时会误销毁订阅。已改为无条件 watch + 空 id 兜底。（该页已整体删除，但这条纪律在其余页面继续遵守。）
9. **`generatePlanFor` 被重复调用** —— 建档提交时 `addPet` 内部已按 `skipPlanCodes` 生成过计划，弹层里又调了一次不带 skip 的版本，会把用户刚勾掉「已打过」的疫苗重新排回来。已改为由 `addPet` 统一生成并暴露 `lastPlanCount`。
10. **`num.clamp()` 返回 `num`，`Slider` 的 `value` 只吃 `double`** —— 体重滑块的初值用 `lastKg.clamp(min, max)` 算出来，类型推断是 `num`，直接塞 Slider 编译不过。必须补 `.toDouble()`。
11. **测试里抄了一份 DDL** —— `repository_test.dart` 原本自带一张 `petAppSchema` 常量表和 `version: 1`，给 `walk_sessions` 加 `mood` / `note` 之后，那份副本完全没有这两列，但因为是独立副本，编译期一点不报错，只会在跑 `setFeedback` 时炸。已改为直接引生产的 `onCreate` + `kSchemaVersion`，**测试和不能再各走一条路**。
12. **迁移不写测试等于没写** —— 迁移语句一旦发出去就再也不能改，但「改了才发现」通常发生在用户升级之后。补了一条「把 v2 语句回放打到 v1 快照表上」的测试，用固化的旧 DDL 建表再 ALTER。

## 最容易踩的坑

### 1. 把平台差异当成区域差异

`Platform.isAndroid` 是平台差异，`AppRegion.isCn` 是市场差异，两者正交。  
混在一起写，后面会变成一团无法维护的条件判断。

### 2. 让 `recordedAt` 和 `createdAt` 混用

补录历史是高频操作（用户会把纸质的疫苗本补进 App）。  
一旦混用，时间线会错乱，而且**数据写进去之后很难再修**。  
`repository_test.dart` 里有三条测试专门守这个。

### 3. 忘了轨迹点是高频写入

GPS 每秒一个点，一次遛狗 30 分钟就是 1800 个点。  
逐条 insert 会卡住 UI 线程。`walk_repository.dart` 用分批 batch + 事务解决，  
且有测试对比批量和逐条的耗时。

### 4. 颜色散落在页面里

改版时把 `AppColors` 抽出来是有原因的：参考稿一次调了主色、底色、描边、  
文字三级和五组图标底色。如果这些写在 6 个页面里，下次换肤要改 60 处。  
**新页面一律从 `core/theme.dart` 取色，不要写 `Color(0x...)`。**

### 5. 环境问题伪装成代码问题

本机出现过两次「工具跑不起来」：  
一次是残留 `flutter_tester` 锁住 `sqlite3.dll`，一次是命名管道耗尽。  
两次都不是代码问题。判断方法：跑个最小探针（比如 `dart` 里  
`Process.run('cmd.exe', ['/c','echo','x'])`），  
如果连它都失败，就不要再改代码了，先修环境。

### 6. 删页面时忘了它带走的符号

`SectionHeader2` 曾定义在 `discover_screen.dart` 里。删整页之前必须先搜  
这个文件里还定义了哪些公共符号、谁在用 —— 否则编译期才炸。  
删文件前先跑：`grep -rn "<被删文件里的公共类名>" app/lib app/test`。

### 7. 加字段后忘了 l10n 与测试

新增文案 key 只改一张语言表、或者漏改 `widget_test.dart` 里的 key 清单，  
都不会在写代码时暴露。**每轮收尾固定跑三件事**：  
zh/en 键集合比对、`L.t` 引用反查、测试文件里硬编码的 key 清单搜索。

### 8. 同一件事做了两遍

建档提交时 `addPet` 内部已生成计划，弹层里又调了一次 `generatePlanFor`。  
第二次调用没带 `skipCodes`，把用户刚勾掉「已打过」的疫苗排了回来。  
**加了参数之后，要顺着所有调用路径走一遍，确认没有不带新参数的旁路。**

### 9. `const` 上下文里放了非 const 的东西（2026-09-29 实测）

两个真实报错，都只在 **release 编译**时才炸（`flutter test` 抓不到 ——
测试文件没 import 这两个页面，那些文件根本没被编译）：

```
records_screen.dart:527  Cannot invoke a non-'const' constructor
                         where a const expression is expected.  const FlDotCirclePainter(
profile_screen.dart:171  Context: The invocation of 'header' is not allowed
                         in a constant expression.  gradient: AppGradients.header,
```

- `fl_chart` 的 `FlDotCirclePainter` **没有 const 构造函数** → 去掉 `const`
- `AppGradients.header` 当时声明成 `static LinearGradient header = const ...`
  （**字段本身不是 const**）→ 改成 `static const LinearGradient header = ...`

**教训**：`flutter analyze` 能在 30 秒内抓到这类错误，而 release 构建要 2 分钟+。
**构建前先跑 analyze**，别拿慢构建当探针。另外：**`flutter test` 覆盖不到的页面
不会被编译**，所以「测试全绿」不等于「能构建」。

### 10. sqflite 的内存库按「路径」缓存，测试里的"老库"可能是假的

迁移测试想造一个 v1 老库，用了 `inMemoryDatabasePath`（固定就是 `':memory:'`），
结果 sqflite 的**单例连接缓存**把 `setUp` 里已开好的 v2 生产库原样返回了 ——
变量名叫 `old`，实际是新的。迁移语句撞上已存在的列：

```
SqliteException(1): duplicate column name: mood
Causing statement: ALTER TABLE walk_sessions ADD COLUMN mood TEXT
```

修法：`OpenDatabaseOptions(singleInstance: false)`。

**教训**：在同一个 `setUp` 下有共享连接时，开第二个内存库必须
`singleInstance: false`，否则你以为在测历史版本，其实在测当前版本。

### 11. pub 缓存缺包时，报错会指向 Flutter SDK 自身源码

```
star_border.dart:536  The getter 'Matrix4' isn't defined for the type '_StarGenerator'.
```

看着像 SDK 坏了，实际是 `package:vector_math` 没下下来 → import 解析失败 →
符号不在作用域 → 编译器把它报成「在所属类上找不到该 getter」。

**排查顺序**：打开报错的 SDK 文件看它 import 了什么 → 验
`.dart_tool/package_config.json` 里指向的路径**是否真的存在** → 缺包就 `flutter pub get`。
**别顺着错误信息去查被点名的那个类名。** 详见
`docs/环境阻塞-flutter管道问题.md`。

### 12. `num.clamp()` 返回 `num`，不是 `double`

`Slider.value` 只吃 `double`，直接传 `clamp()` 的结果编译不过。
写成 `.clamp(min, max).toDouble()`。

### 13. Android 层：漏配 Gradle / Manifest，**不报错但功能静默失效**

这一层最容易骗人 —— 编译全过、测试全绿、APK 也出得来，但装到手机上功能是坏的。

**（1）`flutter_local_notifications` 必须开 core library desugaring**

不开连构建都过不去：

```
Execution failed for task ':app:checkReleaseAarMetadata'.
  Dependency ':flutter_local_notifications' requires core library desugaring
  to be enabled for :app.
```

`android/app/build.gradle.kts`（Kotlin DSL，注意不是 Groovy 的写法）：

```kotlin
android {
    compileOptions {
        isCoreLibraryDesugaringEnabled = true   // Groovy 里叫 coreLibraryDesugaringEnabled true
        sourceCompatibility = JavaVersion.VERSION_17
        targetCompatibility = JavaVersion.VERSION_17
    }
}
dependencies {
    coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.4")
}
```

版本 `2.1.4` 是插件官方 README 指定的（AGP 7.4+ 用 2.x）。
插件自身用 AGP 8.11.1，**项目 AGP 更高（我们 9.1.0）不用降**。

**（2）Manifest 缺权限和 receiver —— 这个连报错都没有**

必须补（`android/app/src/main/AndroidManifest.xml`）：

| 缺什么 | 后果 |
|---|---|
| `POST_NOTIFICATIONS` | Android 13+ 一条通知都弹不出来 |
| `RECEIVE_BOOT_COMPLETED` | 重启后已排期的提醒**全部丢失** |
| `ScheduledNotificationReceiver` | 到点不弹 |
| `ScheduledNotificationBootReceiver` | 重启/更新后不重排 |

**注意区分**：我们用 `AndroidScheduleMode.inexactAllowWhileIdle`（非精确闹钟），
所以**不需要** `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` ——
正好避开 Google Play 对精确闹钟的申报要求。**改精确闹钟要同时加权限 + 后台申报。**

**教训**：Android 层的配置缺失有两类，处理方式完全不同 ——
一类是「构建期就炸」（如 desugaring，好在有明确报错指向任务名），
一类是「装上去才发现功能没了」（权限、receiver、provider）。
**上真机验收时，通知/权限/后台这些必须手动走一遍，不能只看构建成功。**

### 14. AGP 9 起，flavor 里不能再用 `resValue()`（2026-09-30 实测）

双市场分包时想给两个 flavor 不同的应用名，最直觉的写法是：

```kotlin
create("cn") {
    resValue("string", "app_name", "我的宠物")   // ❌ 构建直接失败
}
```

报错：

```
A problem occurred configuring project ':app'.
> Product Flavor cn contains custom resource values, but the feature is disabled.
```

**AGP 9.0+ 起 flavor 的自定义资源值默认被禁用。**
（不是配错了什么开关，官方就是改成这样了。）

**正确写法**：每个 flavor 一份 `res/values/strings.xml`，
`AndroidManifest.xml` 里用 `android:label="@string/app_name"`：

```
android/app/src/main/res/values/strings.xml   -> 兜底值（不带 flavor 的临时构建用）
android/app/src/cn/res/values/strings.xml     -> 我的宠物
android/app/src/intl/res/values/strings.xml   -> My Pet
```

`applicationId` 用 flavor 覆盖**不受影响**，只有 `resValue` / 资源值受限。

参考：Flutter 官方《Set up Flutter flavors for Android》里有这条 infoNote。

### 15. 静态成员被实例访问（`instance_access_to_static_member`）

```dart
NotificationService.instance.onReminderTapped = _openReminderFromNotification;  // ❌ error
NotificationService.onReminderTapped = _openReminderFromNotification;           // ✅
```

`onReminderTapped` 声明成了 `static`（`notification_service.dart:58`），
却通过单例 `instance` 去赋值。**这在 Dart 里是 error，不是 warning** ——
`flutter analyze` 会直接报，release 编译也过不去。

**注意区分**：同一个类上，`instance.init()` / `instance.launchPayload()`
是**实例方法**，那样写没问题。**只有声明成 `static` 的成员才必须走类名。**
排查时别一刀切把所有 `X.instance.y` 都改掉。

## M3.4 健康页深化：预防保健台账（2026-09-30）

### 为什么改

健康页原来四块（预防保健 / 体重曲线 / 过敏 / 病史）都在，但「预防保健」
**只读 `reminders`**。于是这两种完全不同的处境在界面上长得一模一样：

- 上个月刚打了狂犬，只是没在 App 里排计划
- 计划排了半年，一次都没去做

两种都只是「有一行」。用户真正要问的那句话——**「这针到底打了没？」**——
恰恰是那一块答不上来的。

### 怎么改

新增 `lib/domain/health_ledger.dart`：把 records（已发生）与 reminders（已排期）
**按分类对账**，每类产出一行「上次 / 下次」。

| 分类 | 事实来自 | 排期来自 |
| --- | --- | --- |
| 疫苗 | `records.type = vaccine` | `reminders.type = vaccine` |
| 体内驱虫 | `deworm_internal` | `deworm_internal` |
| 体外驱虫 | `deworm_external` | `deworm_external` |
| 体检与就诊 | `records.type = medical` | `reminders.type = checkup` |

配套两处界面改动：

1. **快捷记录条**（页首）：体重 / 疫苗 / 驱虫 / 就诊四个 chip，
   直接开对应类型的录入表单（`showAddRecordSheet` 早就收 `initialType`，
   只是没人从这一页调）。**没有这个入口，台账的「上次」永远停在「还没有记录」。**
2. **每行右侧「记一笔」**：同上，落到该行的类型上。

### 几个刻意做的取舍

- **不新增分类枚举**，直接复用 `PlanItemType`。台账的「一行」就是规则集的
  「一类产出」，两套同构枚举迟早会在加疫苗种类时只改一边。
- **只有疫苗和体检两行无条件显示**，驱虫两行「有内容才出现」——
  一只从没驱过虫也没排期的宠物，摆两行「还没有记录」纯属噪音。
  入口没丢：快捷记录条里就有驱虫。
- **提醒「已关闭」不等于「不用做」**：行照样进台账，只加一枚「提醒已关」小标签。
  旧版这里错用了 `profile.healthGood`（「无待办」）来标已关闭的提醒，语义是反的。
- **不碰阈值/评分**：台账只陈述「上次什么时候 / 下次什么时候」。
  首页删掉「状态：良好」是同一条纪律，这一页更不能把它请回来。
- **领域层不 import data**：`buildCareLedger` 收的是拍平后的 `CareFact` /
  `CareSchedule`，映射由界面做。换来的是 `test/health_ledger_test.dart`
  可以纯 Dart 跑 —— 不建库、不造 `PetRecord`，18 条用例覆盖配对与逾期判定。

### 一个写代码时顺手避掉的坑

「记一笔」的回调里**不能捕获循环变量 `i`**：

```dart
for (var i = 0; i < rows.length; i++) ...[
  onLog: () => open(rows[i]),   // ❌ 点击时才求值，越界只是时间问题
]
```

抽成 `_row(context, ref, row, now)` 方法，让闭包捕获**参数**（每次调用独立绑定）。
Dart 的 `for` 变量在语义上确实是 per-iteration 绑定，这里不赌它 ——
换成方法参数是零成本的确定性。




## 回忆相册写入（2026-09-30 补）

### 问题：只读的相册是个死胡同

回忆页签原本只 `watch` `petPhotosProvider`，数据源是**记录上的附件**。
设计意图没错（「回忆」是记录页的另一种读法，用户不用先建相册再传图），
但**只读落地成了死角**：用户打开回忆看到空态，提示写着「给记录加张照片」，
而这一页压根没有加的入口 —— 他得自己猜到「记录 → 点条目 → 详情 → 照片区 +」。

### 改法

1. **页首右侧 + 空态按钮**都放「添加照片」。
   空态里给按钮这条更重要：**空态光说明不给出路等于没说。**
2. 照片落库路径不变，仍是 `AttachmentRepository.addPhoto`。
   但附件**必须挂在一条记录上**（`attachments.record_id` 非空），
   所以新建 `AppActions.addPhotoMemory()` 会顺手建一条 `note` 记录当载体，
   而不是另开一张「无主照片」表。
   换来两个好处：这张照片同时出现在记录时间线里（点得进去、改得了事件时间、
   删得掉），同步走同一条链路，不用为它单独定协议。
3. `payload.kind = 'photo'` 是给界面认的标记。`recordPayloadSummary` 见到
   它就把这条 note 显示成「照片」而不是光秃秃一个「笔记」。
   **标记存库里、文案在展示层取** —— 库里存 i18n 文本，切区或改文案就成历史脏数据。
4. 每个格子**点得进它所属的那条记录**（`recordById[att.recordId]` →
   `showRecordDetailSheet`）。记录表本来就在 `petRecordsProvider` 里缓存着，
   多挂一个 watch 不额外查库。删照片、改时间都在详情页，不在相册里另造一套。

### 取舍：为什么是「建一条记录」而不是「照片独立成表」

独立表要回答一串没有好答案的问题：它在时间线上排在哪？共养的家庭成员能不能看到？
同步怎么分片？软删跟谁走？而挂在记录上，这些问题全部继承现成答案。
代价是记录页会多出「照片」条目 —— 这恰好是用户想看到的（那天拍了张照）。

### 顺手改进

`_addMemoryPhoto` 里 **在任何 `await` 之前**抓住 `ScaffoldMessenger`，
之后全程不碰 `context`。比 `if (!context.mounted) return;` 那种事后补救
更不容易漏 —— 漏一个 await 分支就是一个 `use_build_context_synchronously`。

### 测试

`test/widget_test.dart` 加两条：新文案中英齐全；
`payload.kind=photo` 的 note 显示成「照片」而**普通笔记不受影响**
（不能把所有 note 都改叫照片）。

## cn 区统一账号接入（2026-09-30）

**起因**：老板拍板 cn 版走 A 方案（共用官网「出岫统一账号」）。完整评估与
实施清单见 `docs/账号体系复用.md`，这里只记对开发有影响的几条。

### 一句话链路

官网验证码登录拿**账号域**令牌 → 宠物服务端换**宠物域**令牌 →
之后全是宠物域的事。cn 区因此**不再需要自己的短信通道**。

### 区域判断只在一个地方

`core/region.dart` 加了 `unifiedAccountBaseUrl`：cn 有值、intl 为 `null`。
调用方写 `if (UnifiedAccountApi.isAvailable)`，**不写 `if (region == cn)`** ——
这正是那个文件开头定的规矩，这次没有为它破例。

### 四条容易踩的

1. **官网令牌不落库**。它只在换票那一次请求里存在。存下来 = 一张凭证
   跨两个信任域长期有效，且两边各自的吊销能力作废。
2. **官网不可达时不建用户**（503 而不是「先建个空号」）。否则一次网络抖动
   建出半个账号，用户下次登录看到两个自己，且没法合并。
3. **不覆盖已有用户的昵称**。宠物圈里的名字和 ERP 账号名可能刻意不同，
   每次登录同步一遍等于把用户改过的名字反复抹掉。
4. **`UNIFIED_ACCOUNT_BASE` 必须带 `www.`**。裸域 `weiyuantool.com` 对
   **所有**请求（含 POST）301 到 www，而 Dart 的 `HttpClient` **对非 GET 的
   301 不自动跟随**（实测 `redirects` 列表是空的，直接拿到 nginx 的 HTML 页）。
   阴险在 **GET 会自动跟随、POST 不会**：手工 curl 探一下 `/api/auth/me`
   看着一切正常，真发码却永远失败，表现是「验证码发不出去 + error (301)」，
   很难联想到域名。已在三处钉死：`region.dart` 默认值、
   `unified_api_test.dart` 的断言、`tool/probe_unified_account.dart`。

### 短信模板：直接复用，不用另报

原先这里写着「模板文案带『出岫』，要另报一个」—— **错了，已更正**。
实查服务器 `/root/财务软件.env` 与阿里云 `QuerySmsTemplate` / `QuerySmsSign`：

| 项 | 实况 |
| --- | --- |
| 签名 | `临沂未远工具`（**公司名**，非产品名） |
| 模板 | `SMS_141655133`，正文 `您正在申请手机注册，验证码为：${code}，5分钟内有效！` |
| 正文里的品牌名 | **没有** |
| `APP_SMS_DEBUG` | 未设置 → 真在发，不会静默降级成回显码 |

所以用户收到 `【临沂未远工具】您正在申请手机注册，…`，从哪个业务发都不违和。
**cn 区短信这一项零阻塞、无报备等待期。**

顺带纠正一个我写错的理解：`scene` **不决定短信模板**。模板查找是
`ALIYUN_SMS_TEMPLATE_{SCENE}` → 回退 `ALIYUN_SMS_TEMPLATE_CODE`，
而服务器只配了后者，所以各 scene 都走同一条。scene 真正的用途是
验证码在 `sms_codes` 表里的**隔离维度**（`_hash_code(phone, scene, code)`）。
由此带来一个**符合预期、别当 bug 修**的行为：cn 区与官网都用 `scene=login`，
所以**在官网发的验证码可以直接拿来登宠物 App** —— 那正是「统一账号」的含义。

### 本地验到什么程度

`server/tests/test_unified.py` 50 项断言**真跑通过**。最关键的几条：
空手机号判成契约破损（空手机号会让唯一键失效、每次登录新建账号）、
官网 401 判成「令牌无效」而 5xx 判成「不可达」（两种给客户端的提示完全不同）、
以及**注释里出现的 `_err(` 不再被误判成调用点**。

客户端这一层还能「真打生产」：`core/region.dart` 零 import、
`unified_api.dart` 只依赖 `dart:*` + `package:http`，**不碰 Flutter** ——
所以 `dart tool/probe_unified_account.dart` 能在本机直接跑（绕开管道 231），
用真正的 `UnifiedAccountApi` 打官网验契约。已双向验证：默认地址全绿并退出 0；
故意传裸域报 2 项失败并退出 1。脚本只发必然被拒的请求，不会真发短信。

## 法律页：商店要的是 URL，不是 App 内的文字

上架时各家商店后台都有一栏「隐私政策链接」，审核方会自己去打开。
App 内嵌的那份（`assets/legal/*.md`）不能代替它。

所以服务端加了三个静态页（`server/legal/`），随服务端发布：

| 页面 | URL |
| --- | --- |
| 隐私政策 | `/legal/privacy` |
| 用户协议 | `/legal/terms` |
| 注销账号 | `/legal/account-deletion` |

三条实现上的讲究：

1. **路由段走白名单**。`/legal/{slug}` 的 slug 是用户输入，直接拼进文件路径
   就是目录穿越。用字典查表，顺带把 `.html` 后缀、连字符/下划线两种写法都
   收进来（商店后台的输入框各式各样，写错一个字符就 404，而审核方看到 404
   会直接判「未提供」）。
2. **文件缺失返回 503 而不是 404**。前者是「这个部署缺文件」，后者是
   「这个页面不存在」—— 审核方对后者的判定是致命的。
3. **注销页单独成页**。国内商店对「注销账号」有明确要求（入口要能找到），
   只写在隐私政策第七节里不够显眼。

HTML 是自包含的（样式内联、零外部依赖），将来想挂到 `weiyuantool.com/pet/`
下直接复制即可，不必改任何东西。

## 版本号：从「记得改」变成「改不了」

老板的原话：「每次更新 要改变版本号，增加1，否则都是一样的。」

问题不在「忘记 +1」本身，而在**这个数字同时存在于两处且没有任何东西校验**：
`pubspec.yaml` 的 `+N` 与服务端的 `APP_BUILD`。漏前者用户收不到更新；
漏后者用户收到提示、装完还是旧版（看起来像更新功能坏了）。

`app/tool/release.ps1` 把四件事绑成一条命令：抬 build → 出包 →
**回读产物里的 versionCode 与 pubspec 核对**（不一致立刻失败）→
打印服务端要改的环境变量。`-DryRun` 只看会变成什么版本，`-NoBump` 复用已抬的号。

### 两个 Windows 上的坑（都实测踩过）

1. **含中文的 `.ps1` 必须带 UTF-8 BOM**。命令行里那个老版本的宿主程序对
   无 BOM 文件按 ANSI(GBK) 解，中文注释与引号错位后解析直接失败，报的是
   「字符串缺少终止符」—— 完全指不到编码上。`release.ps1` 与
   `build_apk.ps1` 都已补 BOM。**改这两个文件后要确认 BOM 还在。**
2. **写回 pubspec 要保 LF**。`WriteAllLines` 会按平台换成 CRLF，导致
   「整个文件都改了」的假 diff。改成自己拼字符串并把原换行风格记下来。

## 顺带修掉的一个坑：204 路由不能写 `-> None`

加法律页时导入服务端发现**服务起不来**：

```
AssertionError: Status code 204 must not have a response body
```

根因和 204、响应体都没关系：`main.py` 开头有
`from __future__ import annotations`，所有注解变成字符串，
FastAPI 注册路由时把 `"None"` 求值成 `NoneType` —— 它不等于 Python 的
`None`，于是 FastAPI 认为这个 204 路由带了 response_model，直接断言失败。

**报错发生在导入模块时**（即服务根本起不来），且信息完全不提注解，
很容易被误诊成「204 不能这么写」。试过 `response_class=Response`，一样失败。

修法：这类「什么都不返回」的路由**不写返回注解**。
（写 `-> None` 反而会让 200 路由在校验响应时要求「必须返回 None」，
